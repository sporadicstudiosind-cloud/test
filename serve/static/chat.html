Send a prompt through the router

This is an experimental chat model; its replies are not reliable. The bundled rung is 34 M parameters fitted for 800 steps on a synthetic corpus; measured against independent computation it scores at or below a prompt-ignoring baseline on four of five task families. It has not been trained on the chat-role format yet.

What is real on every request is the telemetry beside the reply: which superstacks the router selected, how far the focus ladder went into each, how many ponder loops the halting head spent, and what that cost in wall time. Those mechanisms are the point of the architecture, and you are watching them actually run.

One container, one process: serve/server.py running the real iridium package on the selected PyTorch device. Telemetry comes from the model's own routing decision, not from a description of it.
